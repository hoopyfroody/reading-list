# Reading List

A single-user list of web pages to read later, captured from a Mac or an Android phone and readable on both. The interface is a static site on GitHub Pages; the list itself is a markdown file in a separate private GitHub repo.

## Language

### The list

**Item**:
A single web page saved to be read later. Its Normalized URL is its identity.
_Avoid_: Article, link, bookmark, entry, bookmark

**Normalized URL**:
The canonical form of an Item's URL, and therefore its primary key: lowercase host, no `www.`, `https` scheme, tracking parameters stripped, no trailing slash. Two URLs that normalize alike are the same Item.
_Avoid_: Canonical URL, slug, key

**Reading List**:
The Items that are not yet Read. This is the default view and the thing the app is named after.
_Avoid_: Queue, inbox, backlog, unread list

**Archive**:
The Items that are Read. Retained indefinitely and hidden behind a deliberate toggle, so that "what did I read this year" remains answerable. The toggle that reveals the Archive is the only "show me the hidden ones" control in the app — Removed Items are not hidden, they do not exist.
_Avoid_: History, done, completed, removed items, deleted items

### States and actions

**Read**:
The state of an Item you are finished with. A toggle, not a one-way door — an Item can be marked unread again. Marking Read moves an Item from the Reading List to the Archive; it never destroys it. Note the pull towards calling this "removing" — it does take the Item off the list you look at — but Remove is a different, destructive verb, so say Read.
_Avoid_: Done, finished, completed, removed, archived (as a verb)

**Remove**:
Destroying an Item and any record that it existed. Deliberately distinct from marking it Read — Remove means "I don't want this *and* I don't want the history."
_Avoid_: Delete, archive, dismiss, trash

**Star**:
A mark on an Item saying it matters more than the rest. Starred Items are pinned above the others in the Reading List. A rescue mechanism against newest-first ordering burying things, not a priority scale — there is exactly one level.
_Avoid_: Priority, favourite, pinned, important, flagged

**Capture**:
The act of getting an Item into the Reading List, from wherever you encountered it. Has two paths with deliberately different trade-offs: the Skill and the Share Target.
_Avoid_: Add, save, import, clip

**Backfill**:
Filling in Descriptions for Items that were Captured without one. Reconciles the two Capture paths after the fact.
_Avoid_: Enrich, hydrate, sync metadata

### Item metadata

**Title**:
What a page calls itself, captured verbatim from wherever the URL came from. Never invented.
_Avoid_: Name, headline, heading

**Description**:
A short summary of what an Item is, either supplied by you or generated by reading the page. Always distinct from Title, and may be absent on Items Captured via the Share Target until Backfilled.
_Avoid_: Summary, note, excerpt, blurb, comment

### Capture paths

**Skill**:
The Claude Code skill that Captures an Item from a URL, generating a Description by reading the page when one is not supplied. Also performs Backfill. The high-quality, high-friction path.
_Avoid_: CLI, importer, agent, command

**Share Target**:
The installed Android PWA's entry in the system share sheet. Captures URL and Title in two taps and leaves Description absent. The low-friction, low-metadata path.
_Avoid_: Share sheet, share extension, quick add
